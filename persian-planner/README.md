# دفتر (Daftar)

پلنر فارسی با تسک، یادداشت (با استیکر و پیوست)، و دفتر خاطرات — همراه با تقویم شمسی و میلادی توأمان.

## وضعیت فعلی این اسکلت (MVP)
- ساختار کامل پروژه‌ی Kotlin + Jetpack Compose + Room
- سه بخش اصلی هم‌وزن: کارها / یادداشت‌ها / خاطرات، با ناوبری پایین صفحه (آیکون‌ها هم‌خانواده: CheckCircle، EditNote، AutoStories)
- تم بصری «کاغذی مدرن گرم» (پس‌زمینه‌ی کرم، لهجه‌ی ترکوتا/طلایی/زیتونی)، آماده برای دارک‌مود اختیاری
- لوگوی اختصاصی: نوت‌بوک با صحافی مارپیچی، نشانک، و نماد قلم (در `drawable/ic_launcher_foreground.xml`)
- تبدیل تاریخ شمسی↔میلادی به‌صورت آفلاین و بدون کتابخانه‌ی خارجی (در `util/JalaliCalendar.kt`)
- دیتابیس محلی (Room) برای کارها، یادداشت‌ها، و خاطرات — کاملاً کار می‌کند بدون نیاز به اینترنت
- استیکر نمونه (ایموجی) روی یادداشت‌ها — جای‌گذاری‌شده برای جایگزینی با آرت واقعی

## قابلیت‌های تازه اضافه‌شده
- **یادآوری با نوتیفیکیشن:** هنگام ساخت یک کار می‌توان «یادآوری» را فعال کرد، امروز/فردا و ساعت دقیق را انتخاب کرد؛ نوتیفیکیشن با AlarmManager در همان لحظه ارسال می‌شود و پس از ری‌استارت گوشی هم دوباره زمان‌بندی می‌شود.
- **ویجت صفحه‌ی اصلی:** ویجت «کارهای امروز» که کارهای انجام‌نشده را نشان می‌دهد و با هر تغییر در لیست کارها خودکار به‌روزرسانی می‌شود.
- **پیوست عکس، فایل، و صدا:** در یادداشت‌ها و خاطرات می‌توان عکس (چندتایی)، هر نوع فایل/سند، یا یک یادداشت صوتی ضبط‌شده پیوست کرد.

### مجوزهای لازم (در Manifest اضافه شده‌اند)
POST_NOTIFICATIONS، SCHEDULE_EXACT_ALARM/USE_EXACT_ALARM، RECEIVE_BOOT_COMPLETED، READ_MEDIA_IMAGES، RECORD_AUDIO.
روی اندروید ۱۳+ برنامه هنگام اجرا مجوز نوتیفیکیشن را درخواست می‌کند.

## آخرین دور تغییرات (تایم‌لاین، شیشه‌ای، قلم، تم تیره)
- **پیوست‌ها واقعاً قابل دیدن/پخش شدن:** عکس‌ها به‌صورت تامبنیل نمایش داده می‌شن (با تپ باز می‌شن)، فایل‌ها با تپ با اپ مناسب باز می‌شن، و یادداشت صوتی دکمه‌ی پخش/توقف واقعی داره.
- **استیکر در خاطرات هم اضافه شد** (قبلاً فقط یادداشت‌ها داشتن).
- **تم تیره:** از تنظیمات می‌تونی بین روشن/تیره/هماهنگ با سیستم انتخاب کنی.
- **یادآوری ساده‌تر شد:** به‌جای دیالوگ تودرتوی سخت، حالا چیپ‌های آماده (صبح ۹، ظهر ۱، عصر ۶، شب ۹) هست + یه گزینه‌ی «زمان دلخواه».
- **تایم‌لاین کارها:** تب جدید که کارها رو به‌ترتیب تاریخ، روی یه خط زمانی عمودی نشون می‌ده.
- **حس شیشه‌ای/مدرن:** کارت‌های یادداشت، نوار بالا، و نوار پایین حالا نیمه‌شفاف با یه حاشیه‌ی نوری ظریف هستن (بدون نیاز به بلور واقعی، پس روی همه‌ی نسخه‌های اندروید یکسان کار می‌کنه).
- **رسم با قلم:** توی یادداشت‌ها، دکمه‌ی «✏️ رسم با قلم» یه بوم تمام‌صفحه باز می‌کنه که روی دستگاه‌های قلم‌دار به فشار قلم حساسه (خط ضخیم‌تر با فشار بیشتر)؛ نتیجه به‌صورت عکس ضمیمه می‌شه.
- **لوگو با گرادینت:** جلد دفترچه و نشانک حالا سایه‌روشن دارن برای حس عمق بیشتر.


## قدم بعدی فوری: باز کردن در Android Studio
1. پوشه‌ی `persian-planner` را در Android Studio (نسخه‌ی Koala یا جدیدتر) باز کن، Gradle Sync بزن.
2. فونت سفارشی لازم نیست — اپ از فونت خود سیستم (Serif برای عنوان‌ها، Sans-Serif برای متن) استفاده می‌کند که فارسی را هم به‌درستی نمایش می‌دهد؛ این یعنی هیچ فایل خارجی‌ای برای کامپایل لازم نیست.
3. آیکون اپ از قبل با گرادینت و جزئیات طراحی شده (`drawable/ic_launcher_foreground.xml`)؛ اگر خواستی می‌توانی بعداً با یک لوگوی اختصاصی‌تر جایگزینش کنی.

## نقشه‌ی راه درآمدزایی (اولویت‌بندی‌شده)
1. **مرحله‌ی اول (رایگان + تبلیغات):** افزودن Google AdMob — بنر پایین صفحه در نسخه‌ی رایگان، تبلیغ بین‌صفحه‌ای هنگام تعویض تب (با محدودیت فرکانس تا آزاردهنده نشود).
2. **اشتراک Pro (Play Billing Library):** حذف تبلیغات، رنگ/استیکر/فونت‌های نامحدود، پشتیبان‌گیری ابری (Firebase یا Google Drive API)، ویجت صفحه‌ی اصلی.
3. **بسته‌های استیکر:** به‌عنوان محصول مصرفی/غیرمصرفی داخل‌برنامه‌ای (In-app product)؛ می‌توان فصلی (عید، محرم، تابستان) طراحی و فروخت.
4. **کتاب سالانه‌ی خاطرات:** خروجی PDF زیبا از خاطرات یک سال، با گزینه‌ی چاپ فیزیکی از طریق سرویس‌های چاپ‌محور (upsell فاز بعدی، نه MVP).

## معماری فنی برای مراحل بعد
- `data/` : Entity ها، DAO ها، دیتابیس Room، ViewModel ها (آماده و فعال)
- `ui/screens/` : سه صفحه‌ی اصلی (قابل توسعه: صفحه‌ی تنظیمات، صفحه‌ی گزارش‌گیری مثل پروژه‌ی نوتیفای قبلی)
- `ui/theme/` : رنگ، تایپوگرافی، تم روشن/تاریک
- `util/JalaliCalendar.kt` : تبدیل تاریخ، کاملاً آفلاین

## دو زبانه شد (فارسی + انگلیسی)
تمام متن‌های اپ به‌جای این‌که مستقیم توی کد Kotlin نوشته شده باشن، حالا از فایل‌های منبع می‌آیند:
- `res/values/strings.xml` → پیش‌فرض/انگلیسی (وقتی زبان گوشی چیزی غیر از فارسی باشه)
- `res/values-fa/strings.xml` → فارسی (وقتی زبان سیستم روی فارسی باشه)

یعنی اپ **خودکار** بر اساس زبان سیستم‌عامل گوشی بین فارسی و انگلیسی سوییچ می‌کنه (نیازی به دکمه‌ی تغییر زبان داخل اپ نیست، مگر بخوای بعداً یکی اضافه کنیم). جهت متن (راست‌به‌چپ/چپ‌به‌راست) هم خودش با تغییر زبان هماهنگ می‌شه. حتی نام ماه‌های شمسی هم برای حالت انگلیسی به تلفظ لاتین (Farvardin, Ordibehesht, ...) تبدیل می‌شن.

برای تست: روی گوشی/شبیه‌ساز برو به Settings > System > Languages، فارسی یا انگلیسی رو اول لیست بذار، و اپ رو دوباره باز کن.

## چطور خروجی APK بگیری

### روش ۱: از داخل Android Studio (ساده‌ترین راه)
1. پروژه رو در Android Studio باز کن و صبر کن Gradle Sync تموم بشه.
2. از منو بالا: **Build → Build Bundle(s) / APK(s) → Build APK(s)**
3. وقتی تموم شد، پایین صفحه یه نوتیفیکیشن میاد با لینک «locate» — APK رو اونجا پیدا می‌کنی (مسیر معمول: `app/build/outputs/apk/debug/app-debug.apk`)
4. این APK رو می‌تونی مستقیم روی گوشی نصب کنی (برای تست) یا برای دوستات بفرستی.

⚠️ این خروجی «Debug» هست — برای نصب شخصی/تست کاملاً کافیه، ولی برای انتشار در کافه‌بازار/گوگل‌پلی باید نسخه‌ی **Release و امضاشده (Signed)** بگیری.

### روش ۲: گرفتن APK امضاشده (برای انتشار در بازار)
1. از منو: **Build → Generate Signed Bundle / APK**
2. گزینه‌ی **APK** رو انتخاب کن (نه AAB) و Next
3. اگه کلید امضا (Keystore) نداری، **Create new...** رو بزن و یه فایل keystore جدید بساز (رمز و اطلاعاتش رو جایی امن نگه دار — برای هر آپدیت بعدی همین فایل لازمه)
4. Build Variant رو روی **release** بذار و Finish
5. خروجی در مسیر `app/build/outputs/apk/release/app-release.apk` ساخته می‌شه

### روش ۳: خط فرمان (اگه با ترمینال راحتی)
```
# خروجی دیباگ (سریع، برای تست):
./gradlew assembleDebug

# خروجی ریلیز (نیاز به تنظیم امضا در build.gradle.kts داره):
./gradlew assembleRelease
```

### روش ۴: بدون Android Studio — ساخت APK در فضای ابری (GitHub Actions)
اگه اصلاً نمی‌خوای Android Studio نصب کنی، می‌تونی بذاری گیت‌هاب برات APK رو بسازه — رایگان و کاملاً روی سرورهای گیت‌هاب انجام می‌شه، فقط لازمه فایل‌های پروژه رو اونجا آپلود کنی. یه فایل تنظیمات (`.github/workflows/build-apk.yml`) از قبل توی همین پروژه گذاشتم که این کار رو خودکار انجام می‌ده.

**مراحل:**
1. یه حساب رایگان توی [github.com](https://github.com) بساز (اگه نداری).
2. بالای صفحه‌ی گیت‌هاب روی **+ → New repository** بزن، یه اسم بهش بده (مثلاً `daftar-app`)، و **Create repository** رو بزن. نیازی نیست چیزی تیک بزنی.
3. توی صفحه‌ی ریپازیتوری خالی، روی لینک **uploading an existing file** کلیک کن.
4. کل محتوای فایل zip که برات فرستادم رو (بعد از اکسترکت/باز کردن zip روی کامپیوترت) اینجا درگ-اند-دراپ کن — همه‌ی پوشه‌ها و فایل‌ها با هم (پوشه‌ی `app`، `.github`، `build.gradle.kts` و بقیه).
5. پایین صفحه روی **Commit changes** بزن.
6. حالا برو تب **Actions** بالای صفحه‌ی ریپازیتوری — می‌بینی یه Workflow به اسم «Build Debug APK» خودش شروع به اجرا شده (چند دقیقه طول می‌کشه).
7. وقتی علامت ✅ سبز کنارش اومد، روش کلیک کن، پایین صفحه یه بخش به اسم **Artifacts** هست — یه فایل zip به اسم `daftar-debug-apk` اونجاست، دانلودش کن.
8. داخل اون zip، فایل `app-debug.apk` همون APK آماده‌ی نصبه — بفرستش روی گوشیت و نصبش کن.

این روش کاملاً بدون نصب هیچ برنامه‌ای روی کامپیوترت انجام می‌شه — فقط مرورگر لازمه. اگه با Git راحتی، به‌جای آپلود دستی می‌تونی با `git push` هم همین کار رو بکنی، ولی روش بالا برای شروع ساده‌تره.


گوگل‌پلی از سال‌ها پیش دیگه APK قبول نمی‌کنه و فقط **AAB (Android App Bundle)** می‌خواد. برای گرفتنش دقیقاً همون مسیر «Generate Signed Bundle / APK» رو برو ولی به‌جای APK گزینه‌ی **Android App Bundle** رو انتخاب کن. برای کافه‌بازار همون APK امضاشده کافیه. همچنین چون این اپ به دسترسی‌های حساسی مثل SMS یا مخاطبین نیاز نداره، محدودیت خاصی برای تأیید در گوگل‌پلی نداره.
